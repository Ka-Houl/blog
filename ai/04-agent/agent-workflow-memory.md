# Agent、Workflow 与记忆

## Agent 的四个要素

```
         ┌──────── 规划 Planning ────────┐
感知 Perception → 模型推理 → 工具执行 Tools → 观察 Observation → 循环
         └──────── 记忆 Memory ─────────┘
```

| 要素 | 具体形态 |
| --- | --- |
| 规划 | 任务分解、CoT、Plan-and-Execute、反思 Reflection |
| 感知 | 用户输入、检索结果、工具返回、环境状态 |
| 工具 | Function Calling / MCP / 代码执行 |
| 记忆 | 会话历史、用户画像、跨会话长期记忆、工作上下文 |

**ReAct 循环**：`Thought → Action → Observation → Thought …` 直到得到答案或触发终止条件。
它的价值是「可以边做边看结果调整」，代价是循环不可控（需要 recursionLimit、超时、循环检测）。

## Workflow vs Agent：最重要的选型判据

| | Workflow（固定工作流） | Agent（自主规划） |
| --- | --- | --- |
| 路径 | 人预先定义 | 模型运行时决定 |
| 可预测性 | 高，易测试、易审计 | 低，需护栏 |
| 成本/延迟 | 可控 | 可能多轮暴涨 |
| 适合 | 审批流、报表生成、固定 SOP | 开放域调研、复杂排障、探索性任务 |

::: tip 判据
**如果步骤和顺序你能提前画出来，就用 Workflow。**
只有当「下一步取决于上一步的未知结果」且无法枚举时，才交给 Agent 自主规划。
生产系统里更常见的形态是：**Workflow 做骨架，只在个别节点里放一个小 Agent**。
:::

### 四种工作流形态

| 形态 | 例子 | LangGraph 对应 |
| --- | --- | --- |
| 线性 | 摘要 → 翻译 → 校对 | 普通边 |
| 条件 | 按意图路由到不同专家 | Conditional Edges |
| 并行 | 同时检索三个数据源再汇总 | Send API / 并行分支 |
| 人工介入 HITL | 退款金额超阈值需审批 | `interrupt()` + `Command` |

## 记忆：分四层，别都塞进 messages

| 层 | 内容 | 生命周期 | 存储 |
| --- | --- | --- | --- |
| 工作上下文 | 当前任务动态组装的检索片段、中间结果 | 单次运行 | State / Working Context |
| 短期会话 | 最近 N 轮对话 | 会话内 | checkpointer / Redis |
| 用户画像 | 偏好、角色、常用配置 | 长期、可更新 | 业务库 |
| 长期记忆 | 跨会话复用的经验、结论、Case 事实 | 长期、需治理 | 向量库 + 结构化表 |

**上下文工程**就是决定「这一轮窗口里放什么」：

```
System 规则（固定） → 用户画像（少量） → 长期记忆（按需检索）
→ 会话历史（裁剪/摘要） → 检索片段（Top-K + 重排） → 当前问题
```

每条都要有 **token 预算**与**优先级**。窗口满了先压缩历史，再减 Few-shot，最后才砍检索片段。

::: warning 记忆不是越多越好
无差别把历史全塞进窗口，会带来成本上升、延迟增加和「中间信息被忽略」。
长期记忆写入前要判断「是否有复用价值」，否则记忆库会变成噪声库。
:::

## 可靠性：Demo 与生产的分水岭

| 风险 | 工程手段 |
| --- | --- |
| 服务重启丢状态 | 状态持久化（checkpointer），State 是 Source of Truth |
| 重试导致重复写 | 幂等键 / 唯一 ID / Attempt 边界 |
| 死循环烧钱 | `recursionLimit`、步数上限、超时、循环检测 |
| 模型/工具不可用 | 超时降级、多模型 fallback、人工兜底 |
| 客户端断开 | AbortSignal 全链路透传 |
| 出问题查不清 | Trace/Span 记录每个节点的输入输出、耗时、token |

**Attempt 语义**：重试不应创建新任务，而是在同一 Task 下新建一个 Attempt——
这样审计与统计才知道「这是一次重试」而不是「两个任务」。

## Agent 评测

| 指标 | 含义 |
| --- | --- |
| 任务完成率 | 端到端是否达成目标（核心指标） |
| 工具调用准确率 | 选对工具 + 参数正确 |
| 平均步数 / 平均成本 | 效率与成本护栏 |
| 循环/超时率 | 可靠性 |
| LLM-as-Judge | 开放式回答质量，需抽样人工复核 |

配套三件事：固定评测集、固定模型版本与 seed、每次改动留 trace 可回放。

3. 窗口不够用时，裁剪顺序怎么定？
4. 为什么重试要建 Attempt 而不是新 Task？
