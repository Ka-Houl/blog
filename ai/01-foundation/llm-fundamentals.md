# 大模型基础（够用即可）

::: tip 这一章的边界
应用开发岗**不需要动手训练模型**，但必须能解释：模型为什么会幻觉、为什么有上下文限制、
为什么 RAG 能补知识、微调和 RAG 该怎么选。以下按「够应付深问」的深度组织。
:::

## 从 Token 开始

| 概念 | 要点 |
| --- | --- |
| Token / 分词 | 模型读写的最小单位，不是字符也不是词；中文通常 1 字 ≈ 1～2 token |
| Context 窗口 | 单次请求能容纳的 token 总量（输入 + 输出共享额度） |
| 截断策略 | 超出窗口要裁剪历史（保留 System + 最近 N 轮）、压缩摘要或分段处理 |
| 长上下文代价 | 延迟与费用近似线性增长，且存在「中间信息被忽略」的现象 |
| 幻觉 | 模型按概率续写，不查询事实；缺私域知识、知识有截止日期 |

**应用侧结论**：上下文是稀缺资源，所有工程优化（RAG 切分、记忆分层、Prompt 压缩）
本质都是在管理「哪些 token 值得进窗口」。

## Transformer 最小知识链

```
输入 token → Embedding（向量）+ 位置编码
          → 多头自注意力（Q/K/V 计算相关性，因果掩码挡住未来 token）
          → 前馈网络 / 残差 / 归一化（堆叠 N 层）
          → 输出下一个 token 的概率分布 → 采样参数决定选谁
```

| 概念 | 一句话 |
| --- | --- |
| Q / K / V | Query 提问、Key 索引、Value 内容；注意力 = 用 Q 与所有 K 算权重，再加权求和 V |
| 因果掩码 | 训练时遮住未来位置，保证只能根据已生成内容预测下一个 token |
| 位置编码 | 注意力本身不含顺序信息，需显式注入位置 |
| 多头 | 并行多组注意力，分别捕捉不同关系 |
| Scaling Law | 参数、数据、算力按比例放大时能力持续提升（经验规律） |

## 训练链路：四个阶段各解决什么

| 阶段 | 做什么 | 产物 | 应用岗要知道的 |
| --- | --- | --- | --- |
| 预训练 | 海量文本上做「预测下一个 token」 | 基础模型（会续写，但不会听话） | 知识主要来自这里，所以有截止日期 |
| SFT 监督微调 | 用「指令 → 理想回答」样本教它按指令办事 | 对话/指令模型 | Alpaca 格式、chat template、loss mask 只算回答部分 |
| 对齐 RLHF / DPO | 用人类偏好让回答更有用、更安全 | 对齐后的模型 | RLHF = 奖励模型 + PPO（带 KL 惩罚）；DPO 直接用偏好对优化，更轻 |
| 高效微调 PEFT | 只训练少量新增参数 | LoRA / QLoRA 适配器 | 低秩分解 + 量化，消费级显卡可跑；适合**改风格/格式**，不适合灌新知识 |

**蒸馏**属于另一条线：用大模型的输出当软标签训练小模型（CE + KL 损失）。

::: warning RAG vs 微调的决策判据
- 知识需要**频繁更新 / 可溯源 / 有权限隔离** → RAG。
- 需要改变**输出风格、固定格式、领域语气**，且知识相对稳定 → 微调。
- 两者不互斥，企业里常见「RAG 提供事实 + 微调固定格式」。
- 用微调「记住一批文档」通常是错的选择：更新成本高、无法引用、还容易加剧幻觉。
:::

## 通用模型 vs 推理模型

| | 通用模型 | 推理模型 |
| --- | --- | --- |
| 特点 | 响应快、成本低、指令跟随好 | 先生成较长思维链再作答 |
| 适用 | 抽取、分类、格式化、简单问答 | 多步规划、复杂代码、数学与逻辑 |
| 工程注意 | 用结构化输出约束 | 延迟与 token 成本高，别用在高频简单任务 |

另外：**多模态模型**把图像/音频编码进同一上下文；应用侧主要影响是输入构造与计费方式。
